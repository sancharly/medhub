## Objective

Correct the design record of SI-FE-APICLIENT (PRB-044). ADD-023 describes a client "generated from
OpenAPI" and backed by a SOUP item. In fact:

- the client is the hand-written `ApiClient` over the browser `fetch`, with CSRF and RFC 7807
  handling (`frontend/src/api/client.ts`);
- only its request and response types are generated, by the dev tool `openapi-typescript`, into
  `frontend/src/api/generated/`.

The error matters for safety review. SR-031.3's client-side CSRF control (RISK-005) is in-house
code, and has to be reviewed as such. This is a description fix: SR-031 does not change, and
neither does the architecture.

## Implementation detail

1. **ADD-023.** It is approved, so set `version` 1.1, remove the approval record and set
   `in_review`.
   - Responsibility: "Hand-written typed `ApiClient` (`frontend/src/api/client.ts`) over the browser
     `fetch`: session cookie, CSRF header (`withCsrf`, SR-031.3) and RFC 7807 error handling.
     Request and response types are generated from the OpenAPI schema by the dev tool
     `openapi-typescript` into `frontend/src/api/generated/`; the client and its methods are not
     generated."
   - `U-FEAPI-Client`: "hand-written typed client over `fetch` (types generated by

3. Check that no live statement in ADD-023 says the client or its methods are generated (AC-12).
